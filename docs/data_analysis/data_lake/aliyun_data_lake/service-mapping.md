# 服务与术语映射

## 1. 阿里云服务在数据湖中的角色

| 通用概念 | 阿里云对应服务 | 说明 |
| :--- | :--- | :--- |
| 数据湖存储 | OSS（对象存储服务） | 数据的物理存储介质。存储冗余类型建议选"同城冗余"保证高可用。 |
| 元数据服务 | DLF（数据湖构建） | 统一元数据管理平台，提供 Catalog/DB/Table 三层模型。 |
| 数据同步工具 | DTS（数据传输服务） | 将 SQL Server 数据同步到 OSS，支持全量迁移 + 增量同步（CDC）。 |
| 计算引擎 | EMR（E-MapReduce）、DataWorks、MaxCompute | 对湖中数据做 ETL 清洗、建模和分析。 |

## 2. 每个服务通俗解释

### 2.1 OSS（对象存储）

阿里云版的"网盘"，但面向海量数据、按量计费、高可靠。数据湖的物理文件（Parquet/Delta）都放在 OSS 的 Bucket 里。

- **Bucket**：OSS 里的顶层容器，相当于一个"根目录/桶"。
- **存储冗余类型**：
  - 本地冗余（LRS）：数据在单个可用区内多副本，便宜。
  - **同城冗余（ZRS）**：跨可用区冗余，高可用，推荐用于生产数据湖。

### 2.2 DLF（Data Lake Formation，数据湖构建）

阿里云的"元数据管理中心"，也提供入湖任务管理。它把 OSS 里的文件"登记"成 Catalog → Database → Table，让计算引擎能像查数据库一样查数据湖。

### 2.3 DTS（数据传输服务）

负责把源数据库（SQL Server）的数据搬到 OSS。关键能力是**增量同步（CDC）**：源库有新变更时，实时同步到湖里，而不是每次全量重拉。

### 2.4 EMR（E-MapReduce）

托管的大数据计算平台（Spark/Hive/Flink 等）。入湖之后用它跑 SQL 做清洗和建模。创建 EMR 集群时选择 **"DLF 统一元数据"**，即可让 EMR 直接读写 DLF 里的表。
