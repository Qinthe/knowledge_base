# OSS 目录结构规划详解

## 1. 为什么要规划目录结构？

目录结构规划是指在 **OSS Bucket** 内按一定逻辑创建文件夹层级，存放不同来源、层次、时间的数据。**好的目录结构是数据湖可治理、易扩展的基础**，影响权限控制、数据发现、查询性能和成本管理。

## 2. 推荐结构

遵循 **"主题域 → 数据层级 → 数据源/主题 → 日期分区"** 的层级设计：把分区字段（日期）放在最底层，高层的"层/源"便于统一授权。

```text
oss://{your-bucket-name}/                           # 1. Bucket 根路径
├── lakehouse/                                      # 2. 数据湖根目录
│   ├── bronze/                                     # 3. 贴源层(Bronze)
│   │   └── sqlserver/                              # 4. 数据源名称
│   │       ├── db_orders/                          # 5. 源数据库名
│   │       │   ├── orders/                         # 6. 源表名（Delta 格式）
│   │       │   │   ├── dt=2026-09-07/             # 7. 日期分区
│   │       │   │   │   ├── part-0001.parquet
│   │       │   │   │   └── part-0002.parquet
│   │       │   │   └── dt=2026-09-08/
│   │       │   └── order_items/
│   │       └── db_crm/
│   │           └── customers/
│   ├── silver/                                     # 3. 明细层(Silver)
│   │   ├── trade/                                  # 4. 主题域
│   │   │   ├── orders_cleaned/                     # 5. 清洗后的事实表
│   │   │   │   ├── dt=2026-09-07/
│   │   │   │   └── dt=2026-09-08/
│   │   │   └── order_items_cleaned/
│   │   └── dim/
│   │       ├── dim_customer/                       # 5. 维度表
│   │       └── dim_date/
│   ├── gold/                                       # 3. 汇总层(Gold)
│   │   └── sales/                                  # 4. 主题域
│   │       ├── daily_sales_summary/               # 5. 按日汇总宽表
│   │       └── monthly_sales_summary/
│   └── tmp/                                        # 临时目录（中间结果）
```

## 3. 目录层级命名规范

| 层级 | 命名建议 | 示例 |
| :--- | :--- | :--- |
| 数据层级 | 固定 `bronze` / `silver` / `gold` | `bronze` |
| 数据源/主题域 | 业务含义的小写英文 | `sqlserver` / `sales` |
| 数据库名 | 源库名 | `db_orders` |
| 表名 | 源表名 | `orders` |
| 分区 | `字段=值` 形式 | `dt=2026-09-07` |

## 4. 这样设计的好处

- **权限控制**：按"层"授权（只给数据科学家开放 Silver 层）或按"源"授权（只给财务组开放 `db_orders`）。
- **数据发现**：看到路径就能理解来源和层级，避免"数据沼泽"。
- **简化维护**：对 `/bronze/` 目录统一设置生命周期策略（如 30 天转低频存储）即可优化成本。
