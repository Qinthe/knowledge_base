# 详细入湖操作步骤

本节是核心：把 SQL Server 数据实时同步进数据湖，共五个步骤。

> 名词提醒：下文"控制台"均指阿里云 Web 控制台（console.aliyun.com），在左上角搜索框输入服务名即可进入对应控制台。

## 步骤一：创建 OSS Bucket 与目录

1. 进入 **OSS 控制台** → 点击"创建 Bucket"。
2. **Bucket 名称**：如 `sqlserver-lake-prod`（全局唯一，不能与别人重复）。
3. **地域**：选择与源库相同的地域。
4. **存储冗余类型**：选择 **同城冗余（ZRS）**。
5. 创建完成后，进入 Bucket，按《目录结构规划》创建 `lakehouse/bronze/sqlserver/` 等文件夹。

> OSS 的"文件夹"本质是带 `/` 的对象名，在控制台直接点击"新建目录"即可。

## 步骤二：在 DLF 中创建元数据库（Database）

1. 进入 **DLF 控制台** → 元数据管理 → 元数据库。
2. 点击"创建元数据库"：
   - **元数据库名称**：如 `ods_sqlserver_db`（`ods` 是贴源层的习惯前缀）。
   - **存储路径（Location）**：**必须**指向 OSS 中对应的物理路径，例如 `oss://sqlserver-lake-prod/lakehouse/bronze/sqlserver/`。
3. 点击确定。

> 这一步把"物理存储"和"元数据"关联起来：以后在这个库下建的表，数据文件都会落在该 Location 之下。

## 步骤三：配置数据源

1. **DLF 控制台** → 数据入湖 → 数据源管理 → 创建数据源。
2. **连接类型**：选择 **SQL Server**。
3. **实例类型**：选择"云实例"（RDS）或"自建"。
4. 填入连接信息：VPC、VSwitch、安全组、数据库账号密码、库名。
5. 点击"**连接测试**"，确保连通后再保存。

> 连通失败先排查：白名单是否加了 DTS 网段、账号密码是否正确、安全组是否放行。

## 步骤四：创建实时入湖任务（核心中的核心）

1. 进入"**入湖任务管理**" → 新建入湖任务。
2. **任务类型**：选择 **"关系数据库实时入湖"**。
   - 该选项内部调用 **DTS** 服务，支持**全量迁移 + 增量同步（CDC）**，是实现实时同步的关键。
3. **配置源端**：
   - 选择步骤三创建的 SQL Server 数据源。
   - 勾选要同步的表（如 `employees`、`orders`）。
4. **配置目标端**（重中之重）：
   - **目标元数据库**：选择步骤二创建的 `ods_sqlserver_db`。
   - **目标元数据表名称**：可自定义，建议与源表名一致或加 `_delta` 后缀。
   - **存储格式**：**必须选择 `Delta Lake` 或 `Iceberg`**。这是数据湖支持 ACID 和 Upsert 的基础，决定企业级数据湖的成败。
   - **数据湖存储位置**：系统会根据元数据库 Location 自动生成；也可手动指定更细路径，如 `oss://sqlserver-lake-prod/lakehouse/bronze/sqlserver/employees/`。
5. 保存并启动任务。任务先进入"初始化"状态，随后变为"运行"状态。

> **初始化阶段**：DTS 先做全量迁移，把源表所有历史数据搬入湖中；完成后进入增量同步，源库的新增/修改/删除会持续同步。

## 步骤五：验证数据

1. **DLF 控制台** → 元数据管理 → 查看新建的表是否出现。
2. **OSS 控制台** → 进入对应路径，确认：
   - 生成了数据文件（`.parquet`）。
   - 生成了 Delta Lake 日志目录 `_delta_log`（选 Delta 格式时）。

## 常见问题排查

| 现象 | 可能原因 | 处理 |
| :--- | :--- | :--- |
| 连接测试失败 | 白名单未加 DTS 网段 | 添加白名单后重试 |
| 任务一直"初始化" | 源表数据量大 | 等待全量迁移完成，属正常 |
| 湖里没有 `_delta_log` | 存储格式没选 Delta | 检查任务目标端配置 |
| 增量不同步 | CDC 未开启/权限不足 | 确认源库开启 CDC、账号有权限 |
