# 分层模型（Medallion）详解

## 1. 什么是分层？为什么要分层？

数据湖分层是把数据按"加工程度"组织成不同层级的最佳实践。业界广泛采用 **奖牌（Medallion）模型**：**Bronze（铜）→ Silver（银）→ Gold（金）→ Application（应用）**。

**为什么要分层？** 三个核心原因：

1. **数据质量递进**：每层对数据做一次清洗提纯，越往上业务越信任。Bronze 是"原样"、Silver 是"干净"、Gold 是"可直接用"。
2. **历史追溯**：Bronze 保留原始数据快照，任何计算错误都能回到源头重算，不用重新从源库同步。
3. **职责分离**：数据工程（建层）、数据科学（用 Silver）、BI（用 Gold）各取所需，互不干扰。

## 2. 四层职责详解

### 2.1 Bronze（贴源层 / 原始层）

- **职责**：原始数据"零修改"入湖，作为历史快照。
- **数据特征**：与源端（如 SQL Server）完全一致，是故障恢复和数据重跑的基石。
- **格式**：**必须**使用支持 ACID 的格式（如 Delta Lake），以便处理源端 CDC（变更数据捕获）的增量合并。
- **示例路径**：`/lakehouse/bronze/order_db/order_header/`

### 2.2 Silver（明细层 / 清洗层）

- **职责**：数据清洗与标准化——去重、异常值处理、格式统一、字段映射、维度退化。
- **数据特征**：干净、一致的明细数据，是数据科学家做特征工程和模型训练的主要来源。
- **格式**：推荐 Delta Lake 或 Parquet。
- **示例路径**：`/lakehouse/silver/trade/orders/`（已清洗，带分区）

### 2.3 Gold（汇总层 / 服务层）

- **职责**：面向业务主题的聚合，按业务过程（销售、库存）构建宽表，存储聚合、关联后的数据。
- **数据特征**：极大提升公共指标的复用性，BI 直接消费。
- **格式**：Delta Lake 或 Parquet。
- **示例路径**：`/lakehouse/gold/sales/order_summary_daily/`（按天汇总）

### 2.4 Application（应用层）

- **职责**：直接对接 BI 工具或数据服务，是最终用户消费数据的"成品"。
- **数据特征**：根据具体报表需求裁剪，可能只保留某报表需要的列。
- **格式**：取决于消费工具（常通过视图或特定项目表提供给 Power BI / API）。

## 3. 四层一览表

| 层级 | 层名 | 职责与操作 | 存储格式与示例 |
| :--- | :--- | :--- | :--- |
| 第1层 | Bronze（贴源层/原始层） | 原始数据"零修改"入湖，作为历史快照 | Delta Lake；`/lakehouse/bronze/order_db/order_header/` |
| 第2层 | Silver（明细层/清洗层） | 去重、异常值处理、格式统一、字段映射、维度退化 | Delta Lake/Parquet；`/lakehouse/silver/trade/orders/` |
| 第3层 | Gold（汇总层/服务层） | 按业务主题聚合、构建宽表 | Delta Lake/Parquet；`/lakehouse/gold/sales/order_summary_daily/` |
| 第4层 | Application（应用层） | 对接 BI 工具/数据服务，按报表裁剪 | 视图或项目表；供 Power BI/API |

## 4. 分层决策参考

- 数据规模小、只有一张表？可以简化，但**至少保留 Bronze + Gold 两层**（原始快照 + 汇总）。
- 需要机器学习？务必保留 **Silver**（干净的明细数据是特征工程的输入）。
- 需要多团队共享指标？务必保留 **Gold**（统一口径，避免各自算出来的数对不上）。
